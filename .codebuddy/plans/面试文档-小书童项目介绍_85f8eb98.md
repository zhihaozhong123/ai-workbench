## 用户需求
为「小书童（XiaoShuTong）」项目撰写一份面试用技术文档，用于在技术面试中系统介绍项目，面向后端 / Agent 开发岗位面试官与候选人。

## 产品概述
文档需以面试口径，全面呈现该项目：一个跑在用户本机的 macOS 桌面 AI 助手（Tauri + Vue3 前端 + FastAPI 后端），后端同时支持容器化多实例部署。文档既要讲清"做了什么"，也要讲清"为什么这么做"。

## 核心内容（文档必须覆盖的章节）
1. **项目概述**：产品定位、目标人群、核心能力（聊天 / 知识库问答 / 联网 / 长期记忆 / 本机操控 / 163 发信）。
2. **整体架构**：分层架构图 + 一次聊天请求的完整链路（前端 → nginx → 多副本 backend → Redis/Chroma/PostgreSQL/LLM）。
3. **技术栈清单**：按层（桌面壳 / 前端 / 后端 / Agent / 存储 / 协调 / 鉴权 / 运维）列出所用技术与版本要点。
4. **Agent 功能模块技术点与选型理由**：逐项说明 ReAct+LangGraph 推理、Function Calling 工具调用、混合 RAG（向量+BM25+RRF、零知识）、双层长期记忆（热向量+冷 BM25）、上下文分段隔离、WebSocket 流式输出、失败兜底（超时/退避重试）；每项必须回答"实现方式很多，为什么这样选"。
5. **后端多并发设计**：异步框架、无状态化（状态全外置 Redis）、多副本扩展（1 worker 约束）、Redis 分布式协调原语、信号量跨副本全局上限不被副本数放大、WS 每条消息独立 task 并发、多租户配额 + 应用层限流。
6. **运维如何配合多并发**：nginx 多副本 DNS 轮询负载、探针策略（liveness/readiness 分离）、状态外置服务、可观测性（Prometheus/Loki/Grafana/exporter）、备份与资源约束。
7. **面试高频追问**：归纳可能追问点（如为什么不用多 worker、Chroma HA、Redis 为何必填、语义切分取舍等），便于候选人准备。
