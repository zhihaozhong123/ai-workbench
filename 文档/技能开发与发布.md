# 技能开发与发布手册（XST-Skill v1）

> 面向技能开发者：本手册说明如何在「智作台 AI Workbench」上从零写好一个技能，
> 打包成 `.xskill` 并发布到 GitHub Release，让用户在技能市场一键安装、获得该技能的专属对话 Agent。

技能 = **一个标准目录仓库**：`manifest.json`（权威元数据）+ 技能说明 + 可选确定性 CLI。
平台负责：市场（GitHub Releases 分发）、校验安装（安全解压落盘）、运行时隔离执行、Agent 注入与调度。

## 0. 全链路速览

```
复制 skill-template 写业务
   → manifest.json + SKILL.md + scripts/main.py（可选 CLI）
   → scripts/build_skill.py 打包为 skill-<slug>-<version>.xskill
   → git tag v1.0.0 + GitHub Release 附资产（release_skill.sh 一键）
   → 智作台「技能市场 → 管理技能源 → 添加 owner/repo」同步
   → 用户点「安装」→ 市场页状态变「打开任务」
   → 「对话任务」左侧出现该技能的任务卡片 → 进入专属对话
   → Agent 注入技能系统提示 + 技能 CLI 工具，由主 Agent 调度
```

## 1. 技能目录结构

```text
my-skill/                  # 技能仓库根（即打包内容）
├── manifest.json          # 【权威】XST-Skill 元数据（推荐）
├── SKILL.md               # 给 Agent 看的技能说明（也可作为 system prompt 来源）
├── AGENT.md               # 可选：系统提示文件（由 manifest.system_prompt_file 指定）
├── scripts/
│   └── main.py            # 可选：确定性 CLI（技能要“做事”时必须提供）
├── README.md / CHANGELOG.md / references/ ...
└── tests/                 # 自测（不打进产物前的本地验证）
```

> **没有 manifest.json？** 平台兼容回退读取 `SKILL.md` frontmatter：
> ```markdown
> ---
> name: 联网搜索
> description: 使用 SerpAPI 搜索互联网获取最新信息
> author: your-name
> version: 1.0.0
> metadata:
>   openclaw:
>     slug: web-search
>     emoji: "🔍"
>     category: 工具
> ---
> # 联网搜索
> 给 Agent 的技能说明正文……
> ```
> 因此直接用 skill-template 写好的仓库无需改动即可被识别、打包与安装。

## 2. manifest.json（权威元数据）

```json
{
  "schema_version": 1,
  "slug": "web-search",
  "name": "联网搜索",
  "version": "1.0.0",
  "description": "使用 SerpAPI 搜索互联网获取最新信息",
  "author": "your-name",
  "emoji": "🔍",
  "category": "工具",
  "homepage": "https://github.com/your-name/web-search",
  "runtime": {
    "type": "python",
    "entry": "scripts/main.py",
    "cli": "run",
    "env_whitelist": ["SERPAPI_API_KEY"],
    "timeout_seconds": 60
  },
  "system_prompt_file": "AGENT.md",
  "permissions": ["network"],
  "min_app_version": "0.1.0"
}
```

| 字段 | 必填 | 说明与约束 |
|------|------|-----------|
| `schema_version` | 是 | 固定 `1`（平台当前支持版本） |
| `slug` | 是 | 唯一标识：小写字母/数字/`-`，1~63 字符，字母或数字开头结尾 |
| `name` | 是 | 展示名（任务卡片/市场卡片） |
| `version` | 是 | 语义化版本 `X.Y.Z`；同时作为 GitHub tag（`v` 前缀） |
| `description` | 建议 | 一句话简介，市场搜索/卡片展示用 |
| `author` / `emoji` / `category` / `homepage` | 选 | emoji 缺省回退 🧩；category 缺省 `通用` |
| `runtime.entry` | 条件 | 技能要有可执行工具时必填：相对技能根的 Python 入口（如 `scripts/main.py`） |
| `runtime.cli` | 选 | CLI 子命令，缺省 `run` |
| `runtime.env_whitelist` | 选 | 允许透传给子进程的宿主环境变量名（如 `SERPAPI_API_KEY`）；未列出的任何平台密钥**不会**进入子进程 |
| `runtime.timeout_seconds` | 选 | 单次 CLI 调用超时（默认跟随配置，建议显式给出） |
| `system_prompt_file` | 选 | 相对技能根的系统提示文件（如 `AGENT.md`），内容合并进 Agent 系统提示 |
| `permissions` | 选 | 声明技能需要的能力（`network` 等，当前为声明式） |
| `min_app_version` | 选 | 要求的最低智作台版本，`0.1.0` 起 |

校验规则见 `skills/manifest.py`（`_apply_defaults` / `build_manifest`）；slug / version 均有强校验，不合法会被拒绝安装。

## 3. 技能 CLI 契约（XST-Skill CLI v1）

技能“做事”的唯一入口是**确定性 CLI**，由平台以**安全子进程**方式执行：

- 启动：`python -u <entry> <cli>`，`cwd = 技能目录`；
- 入参：单行 JSON 经 **stdin** 传入 `{"params": {…}}`；
- 出参：单行 JSON 经 **stdout** 返回：
  ```json
  {"ok": true,  "data": {…}}
  {"ok": false, "error": "人类可读错误"}
  ```
- 退出码非 0、超时、输出非法 JSON → 平台判为技能执行失败并返回结构化错误。

最小 CLI 模板（`scripts/main.py`）：

```python
import json
import sys

def main() -> int:
    try:
        payload = json.loads(sys.stdin.read() or "{}")
        params = payload.get("params") or {}
    except json.JSONDecodeError:
        print(json.dumps({"ok": False, "error": "入参 JSON 非法"}, ensure_ascii=False))
        return 1
    # —— 在这里实现你的业务（读 env 中的密钥、联网、计算等）——
    out = {"received": params}
    print(json.dumps({"ok": True, "data": out}, ensure_ascii=False))
    return 0

if __name__ == "__main__":
    raise SystemExit(main())
```

**Agent 视角**：安装后平台把技能 CLI 包装为一个名为 `skill_<slug>` 的 LangChain 工具，
主 Agent（ReAct）自行决定调用时机与参数。技能不需要自己判断“该不该执行”。

**环境与安全**：
- 子进程只继承基础系统变量（`PATH`/`HOME`/`TMPDIR`…）+ `manifest.runtime.env_whitelist` 列出的宿主变量；
  平台自身密钥（DeepSeek、百炼等）绝不进入技能进程；
- 注入固定变量：`XST_SKILL_SLUG`（技能 slug）、`XST_USER_ID`（当前用户 ID）；
- 敏感参数不要写进 stdin / 日志——需要密钥时，声明进 `env_whitelist` 并从 `.env` 注入；
- 全局并发受 Redis 分布式信号量 `skills_run` 限制；单次调用有超时兜底。

## 4. 打包与发布（把仓库变成市场里可装的技能）

在**技能仓库**内：

```bash
# 0) 前置：gh CLI 已登录、仓库已推到 GitHub（public 即可免 token 分发）
gh auth status

# 1) 打包：产物 dist/skill-<slug>-<version>.xskill
uv run --project /path/to/ai-workbench python scripts/build_skill.py .

# 2) 一键发布：打包 + git commit + tag vX.Y.Z + gh release create（附资产）
bash /path/to/ai-workbench/scripts/release_skill.sh .        # 全部执行
bash /path/to/ai-workbench/scripts/release_skill.sh . --dry-run   # 只打包预览
```

`release_skill.sh` 行为：
- tag 取 `manifest.version` 自动补 `v`（如 `v1.0.0`）；已存在则跳过打 tag；
- `gh release create vX.Y.Z <asset>`，附带 CHANGELOG.md 顶部的 `## ` 段落为 Release Notes；
- 失败时提示手动 `gh release create`。

> **版本升级 = 再发一个 Release**：改 `version`（如 `1.1.0`）→ 重新 `release_skill.sh`。
> 用户在技能市场安装过旧版时，市场页会显示「升级」按钮（按版本号比较），一键升级。

## 5. 在智作台接入（安装 / 升级 / 卸载）

1. 打开「技能市场」→ 右上「管理技能源」→ 添加仓库：`owner/repo`（或完整 GitHub 地址）；
2. 「立即同步」：平台拉取该仓库 Releases，解析每个 Release 资产中名为
   `skill-<slug>-<version>.xskill` 的包 → 写入市场快照；
3. 市场页出现技能卡片 → 点「安装」→ 平台执行：校验 manifest（JSON Schema）→
   **防目录穿越（zip-slip）安全解压**到 `data/skills/<slug>/` → 写入 `installed_skills` 注册表；
4. 安装成功 → 「对话任务」左侧出现该技能的任务卡片，点击进入**专属对话**，
   该会话固定注入技能系统提示并挂载 `skill_<slug>` 工具（通用工具仍保留）；
5. 卸载后：技能目录被清理，历史会话与消息保留，只是不再出现在任务入口；
   再次安装同名同版本会直接复用目录（幂等）。

**故障隔离**：单个技能安装失败只影响该技能（安装标记为 failed、从工具链剔除、
对话回退通用 Agent），不影响平台整体；GitHub 拉取失败有 TTL 缓存与重试。

## 6. 最佳实践与安全检查清单

- [ ] `slug` 稳定：发布后不要改 slug，否则老用户会看到“新技能”；
- [ ] 版本语义化：修复 `1.0.1` / 新功能 `1.1.0`，与 Release tag 保持一致；
- [ ] CLI 幂等、确定性：入参出参只用 JSON，别依赖子进程里的交互式输入；
- [ ] 密钥不进包：密钥通过 `runtime.env_whitelist` 从宿主 `.env` 注入；
  技能包内**绝不**写死 API Key；
- [ ] 入口与提示词都放在技能根内（入口越界会被拒绝）；
- [ ] 单次调用控制在超时内（联网类技能注意重试与快速失败）；
- [ ] 给足 `description`，写明“何时适合调用、怎么做”，Agent 才会在正确的时机用你；
- [ ] 先 `--dry-run` 本地验证产物，再真正 push/发布。
